# 가입 연락처 확인과 친구 초대 보상

활성화 후 신규 가입자는 초대 코드 입력 여부와 관계없이 가입에 사용할 국내 휴대폰 번호(010으로 시작하는 11자리)를 인증한다. 기존 회원의 프로필 수정과 내 정보 조회에는 새 인증이 적용되지 않는다.

1. 온보딩 토큰으로 `POST /api/v1/users/onboarding/phone/challenges`에 `{"phone":"01000000000"}`를 보낸다. 응답 데이터의 `recipient`는 1666-3538이고 `text`는 서버가 발급한 문자 내용이다. 사용자가 해당 번호의 휴대폰에서 직접 문자를 보낸다. 발급 시점부터 300초 동안 유효하다.
2. 같은 토큰으로 `POST /api/v1/users/onboarding/phone/confirm`에 `phone`과 발급받은 `challengeId`를 보낸다. `verified: false`면 아직 문자가 조회되지 않았다. 서버가 OCTOMO에서 도착을 확인한 경우에만 `true`가 된다.
3. 같은 토큰과 같은 번호로 기존 `POST /api/v1/users/onboarding`을 호출한다. 인증은 최초 발급 후 5분 이내에 가입까지 완료해야 한다. 가입 실패로 트랜잭션을 롤백하면 유효한 인증도 복원된다. 새 토큰을 받거나 다시 발급하면 해당 세션에서는 새 인증을 사용한다.
4. 발급은 온보딩 사용자별·번호별 각각 5분에 3회, OCTOMO 조회는 발급 건당 5회까지다. 초과하면 `USER-021`(429), 번호·세션 불일치 또는 만료 시 `USER-020`(400)을 반환한다. 외부 오류는 `USER-022`(503)이다.

유효한 초대 코드로 가입한 경우에만 검증한 번호를 기준으로 한 번, 양쪽에 각각 4,000P를 적립한다. 이미 지급된 번호로 탈퇴 후 재가입하면 가입은 완료되고 양쪽 모두 추가 적립은 없다. 현재 활성 회원 간 연락처 중복 제한은 그대로 적용된다. 프로필 연락처를 바꿔도 보상 시점에 기록한 식별값은 바뀌지 않는다.

## 배포와 보관

- V51을 먼저 적용한다. 기본 설정에서는 코드 없는 기존 가입이 가능하다. 유효한 초대 코드가 포함된 가입은 보상 없이 완료되지 않도록 가입 전 `USER-023`(503)으로 거절한다. 클라이언트의 인증·에러·만료 처리 배포와 전체 서버 인스턴스의 설정 전환을 함께 준비한다. 구버전 인스턴스가 미검증 보상을 지급하는 혼합 배포를 피한다.
- 활성 OCTOMO 애플리케이션, 통신 가능 여부 및 잔여 쿼터를 확인한 뒤 비밀 저장소에서 `OCTOMO_API_KEY`와 별도의 `HASHI_INVITE_PHONE_HMAC_KEY`(32바이트 이상의 난수를 Base64 인코딩)를 주입한다. `HASHI_SIGNUP_PHONE_ENABLED=true`일 때만 활성화된다. 운영 키와 실제 전화번호는 테스트에 사용하지 않는다.
- 보상 원장에는 전화번호 원문, 회원 ID 대신 HMAC 식별값 하나만 남는다. 이 값도 사용 목적과 보유 근거가 필요한 정보다. 활성화 전 탈퇴 후 보유 근거·동의/고지와 보관·삭제 기간을 확정한다. 임의 보상 만료 기간은 설정하지 않는다. 키를 단순 교체하면 같은 번호의 과거 지급을 구분할 수 없으므로 키 수명·보관·교체 절차를 먼저 합의한다.
- 가입 인증을 비활성화한 뒤에도 V51을 적용한 서버는 만료된 인증 요청·횟수 제한 행을 정리한다. 요청·응답 본문, 인증 헤더, 전화번호, 발급된 문자 내용을 운영 로그나 추적 시스템에 기록하지 않는다. provider 장애 시 재인증으로 복구한다. 이미 인증한 세션은 유효 기간 내에 가입할 수 있다.
