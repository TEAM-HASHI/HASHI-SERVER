# 일반 식당 검색

`GET /api/v1/restaurants`의 검색 계약입니다. 지도 검색은 별도 API와 정렬 규칙을 유지합니다.

| 요청 | 동작 |
| --- | --- |
| `keyword=스시 라멘` | 식당명·메뉴명·해시태그 중 스시 또는 라멘이 포함된 식당 |
| `keyword=%23스시` | 해시태그에 스시가 포함된 식당. URL의 #은 %23으로 인코딩 |
| keyword 생략 또는 공백 | 기존 식당 목록. 초기 검색 화면에서는 목록 검색 요청을 생략 |
| #만 입력, 태그 내부 공백, 앞뒤 공백 제거 후 30자 초과 | 400 INVALID_INPUT |

대소문자를 구분하지 않고 부분 검색합니다. 여러 단어의 순서와 중복은 결과에 영향을 주지 않습니다.
길이는 Unicode 코드 포인트로 계산합니다. %, _, !는 와일드카드가 아닌 입력 문자 그대로 찾습니다.

| 정렬 | 검색어가 있을 때의 내림차순 기준 |
| --- | --- |
| basic | 일치 단어 수 → 식당명 일치 단어 수 → 메뉴명 일치 단어 수 → 해시태그 일치 단어 수 → 식당 ID |
| popular | 리뷰 수 → 별점 → 식당 ID |
| rating | 별점 → 리뷰 수 → 식당 ID |

예를 들어 `스시 라멘`은 두 단어가 식당명과 메뉴명에 나뉘어 있어도 두 단어가 일치한 것으로 계산합니다.
한 단어가 메뉴 여러 개 또는 여러 태그와 일치해도 그 단어의 점수는 한 번만 계산합니다.
검색어 없는 목록은 기존 basic(ID), rating(별점·ID) 정렬을 유지합니다.

기본 10개, 최대 50개씩 조회합니다. `hasNext=true`이면 응답의 `nextCursor`를 같은 검색 조건으로 전송합니다.
검색어·장르·유형·정렬을 변경하면 커서를 제거하고 처음부터 조회해야 합니다. 페이지 크기는 변경할 수 있습니다.
구형 검색 커서와 조건이 다른 커서는 400입니다. 배포 후 열려 있던 검색 결과는 첫 페이지를 다시 요청해야 합니다.
커서는 데이터 스냅샷이 아닙니다. 조회 중 이름·메뉴·태그·별점·리뷰 수가 수정되면 결과 순서가 달라질 수 있습니다.

결과가 없으면 200과 빈 content, hasNext=false를 반환합니다. 오류 응답과 구분해 빈 화면을 표시합니다.
기존 카드 응답 형태와 장르·큐레이션 필터는 유지합니다. 관리자 해시태그 등록 정책과 자동완성은 이번 변경 대상이 아닙니다.
