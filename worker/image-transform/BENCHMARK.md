# 이미지 변환 성능 확인

변환 방식을 바꾸기 전에 현재 순차 처리의 시간과 메모리를 측정한다. AWS 계정 없이 로컬에서
실행할 수 있지만, 로컬 결과로 Lambda의 timeout이나 메모리가 충분하다고 판단하지 않는다.

worker 디렉터리에서 다음 명령을 실행한다. 입력 생성은 별도 프로세스에서 끝내고, 측정마다
새 Node 프로세스를 사용한다. 원본은 외부에 업로드하지 않는다.

```sh
npm test
node scripts/benchmark.mjs /absolute/path/to/local-image.png
```

측정 스크립트는 RESTAURANT의 후보 9개를 만드는 경우를 대상으로 한다. 작은 이미지라서
9개를 만들 수 없으면 출력의 status와 종료 코드로 구분한다. 프로그램과 입력을 준비하는
시간은 elapsed에서 제외하지만, peak RSS는 Node와 모듈, 원본 버퍼를 포함한 프로세스 전체의
최대 메모리다. 변환 단계만의 메모리나 Lambda의 Max Memory Used와 같은 값이 아니다.

## 로컬 실행 기록

2026-09-14 Windows x64, Node 24.17.0, Sharp 0.35.4에서 합성한 2,000×2,000 반투명 단색 PNG를
한 번 실행했다. 검증과 9개 생성에 약 3.27초, 프로세스 peak RSS는 148,920 KiB였다.
입력은 84,940 bytes, 출력 합계는 4,684 bytes다. 단색 합성 이미지이며 다른 작업이 실행 중인
PC에서 한 번 측정한 값이므로, 실제 사진의 압축률·평균 지연·최악 메모리를 대표하지 않는다.

## 기능 활성화 전 추가 확인

- 실제 사진과 투명 PNG, 상한에 가까운 40MP 입력을 충분한 메모리가 있는 환경에서 반복 측정한다.
- 같은 입력·Node·Sharp·규격으로 비교하고, cold start와 warm 실행을 구분한다.
- dev Lambda에서 S3 읽기·쓰기와 결과 발행을 포함한 Duration, Max Memory Used, timeout을 확인한다.
- 현재 순차 처리로 부족한 경우에만 decode 공유 등의 최적화를 검토한다. 출력 bytes가 바뀌면
  기존 불변 object key와 규격 버전 정책도 함께 검토한다.

위 추가 확인은 아직 완료하지 않았다. 현재 측정만으로 순차 처리의 성능이 충분하다고 결론 내리지 않는다.
